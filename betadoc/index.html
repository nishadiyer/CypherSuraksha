The problem

Three everyday habits quietly leak who you are.

You paste real details into AI chats

Names, emails, ID numbers and keys end up in a third party's logs and, sometimes, its training data. Most people never think about it at the moment they hit send.

Your photos become face-recognition fuel

A selfie posted anywhere can be scraped and matched to you, and it carries hidden location data. Few people strip either.

Faces on video calls can be fake

Scammers now use AI-generated faces to impersonate relatives and colleagues. There is rarely anything in the call window to tell you.

The product

Three shields, one popup, zero uploads. Each shield acts at the moment of risk, on the page you are already using.

PROMPTGUARD · PII

Redacts before you send

Swaps names, emails, phone numbers, card numbers, API keys and your own "never share" words for placeholders like [PERSON_1] on ChatGPT, Claude, Gemini and Copilot. Replies are shown with the real values restored on your screen only.

PIXEL CLOAK · FACES

Cloaks photos on upload

Finds faces in images you upload to social sites, adds an invisible change (at most 8/255 per colour channel) that confuses face-recognition models, and strips location data. A badge offers "Bypass on this site".

TRUTHLENS · VIDEO

Checks faces on calls

Samples video on Google Meet, Zoom Web and WhatsApp Web, crops the face and scores it on-device. A pill shows "No fake found", "Unsure" or "Fake?", and a sustained red opens a clear warning.

Architecture

Content scripts watch the page, a service worker routes requests, and a hidden offscreen page runs one worker per shield with ONNX Runtime (WebGPU first, WASM fallback). Injected UI sits in closed Shadow DOM so pages cannot read or restyle it.

Five invariants, each enforced by tests

  1. Zero network. The CSP blocks every outbound request. An end-to-end test confirms fetch, XHR and WebSocket all fail.
  2. RAM only. Prompts, images and frames are never written to storage; buffers are zero-filled after each inference.
  3. Ephemeral redaction maps. Placeholder-to-value pairs live per tab in session storage and vanish on close or navigation.
  4. Zero-knowledge vault. "Never share" words are stored only as salted SHA-256 hashes.
  5. UI isolation. Everything injected is in closed Shadow DOM.

Deployment notes

This is a client-side product, so there is no server lane to run. "Deployment" means installing the extension and, for demos, serving one static page.

Install

Build once, then Load unpacked from dist/ in chrome://extensions. Or install the packaged zip. Details in the documentation.

Models

Optional files in public/models/. With none, every shield uses a deterministic fallback and the People shield shows an honest "Unverified" state instead of green.

Demo page

A static page plays sample faces as a fake call tile. It needs a separate DEMO build of the extension, so the shipping build never carries the localhost permission.

Try the live demo

There is no login. The demo is a local page plus a separate demo build of the extension, so you see the real shields react in your own browser.

  1. Get the code: github.com/nishadiyer/CypherSuraksha. Run npm install, then npm run build:demo.
  2. In Chrome open chrome://extensions, enable Developer mode, choose Load unpacked, and select dist-demo/.
  3. Open the demo page (demo/index.html, served on port 4186 in our setup) and click Real person, then AI-generated face. Hover the pill to see the numbers.
  4. Open ChatGPT or Claude and type a made-up name, email and phone number to watch PromptGuard swap them for placeholders.
Be aware: the demo plays still pictures. Real calls are live video, where results differ. See the documentation's limits section.
